**docker-compose 서비스:**

```yaml
# docker-compose.yml (요약) — backend 전용
services:
  server:    # Hono + Claude Code CLI
    build: ./backend/server
    ports: ["3000:3000"]
    env_file: .env       # KAKAO_REST_KEY, OPENWEATHER_KEY
    volumes:
      - ${HOME}/.claude:/root/.claude   # ★ CC CLI 인증 (OAuth 토큰) bind mount
    depends_on: [tts]
    networks: [trip-net]
  tts:       # Edge TTS Python
    build: ./backend/ai-tts
    ports: ["8000:8000"]
    networks: [trip-net]
  # (선택) Expo Web을 도커로 serve 하고 싶을 때만:
  web:
    build: ./frontend/mobile-web
    ports: ["19006:19006"]
    profiles: [web]      # 기본 안 띄움. `docker compose --profile web up`
networks:
  trip-net:
    driver: bridge
```

**모바일은 컨테이너 밖.** `bun run mobile` (host에서 metro) → 디바이스에서 `http://<host-ip>:3000` 으로 server 접속. iOS 시뮬레이터 / Android 에뮬레이터 / 실기기 모두 동일.

**한 번에 모두:** `bun run dev` → turbo가 `docker:up` (backend) + `@trip/mobile-web dev` (frontend metro) 동시 띄움.

**전역 state 구조 (Zustand) — 3 store (D5 결정):**

```
stores/
├─ user-style.ts        — { tags, likes/dislikes } (★ persist + AsyncStorage)
├─ trip.ts              — { active: Trip | null, currentLocation: GPS }
└─ session.ts           — { glow, currentCard, turns[], alertQueue[], lastWeatherCheck }
                          (companion + conversation + alert-queue 통합. active session 단위)
```

**user-style persist 명시 (D5):**
```ts
import { persist } from 'zustand/middleware'
import AsyncStorage from '@react-native-async-storage/async-storage'
// in-context memory 유지 — 앱 재시작에도 사용자 학습 살아있음
```

**Active trip 라이프사이클 (alert 트리거) — D3 결정 (foreground only):**
- `trip.active !== null` *AND foreground* 일 때만 60분 polling
- 앱 foreground 진입 시 `last-fetch > 30min` → 즉시 catch-up fetch
- iOS Background App Refresh에 의존 X (60분 보장 X)
- OpenWeather 호출 → 비/추위 감지 시 `session.alertQueue`에 push
- POI 영업종료 체크: 카카오 응답에 hours 있으면 NORMAL 카드 표시 전 필터
- 어느 화면이든 `useSession()` subscribe → 알림 처리
- Push notification은 v2 (Apple Developer 계정 셋업 후)

**크로스 탭 navigation — D4 결정 (intent extraction LLM):**
- ASR 결과를 1-turn LLM call로 intent 추출:
  ```ts
  // intent: 'show_map' | 'show_card' | 'continue' | 'rescue'
  await llm.extractIntent(asrText) // ~200-400ms 추가
  ```
- 단순 keyword substring 매칭 X (한국어 변형/오트리거 위험)
- intent === 'show_map' → `router.navigate('/(tabs)/travel')`
- TTS 음성 모드의 잉크 마크 glow color는 `session.glow` 값 subscribe
- Expo Router로 탭 상태 보존 (스택 unmount 안 함)

**Companion glow state machine (D6):**

```
       ┌─────────┐
       │ NORMAL  │ (default — 청자 dim glow)
       └────┬────┘
            │ weather/POI trigger
            ▼
       ┌─────────┐  user "닫혔어"/"다른 곳"
       │  ALERT  │─────────────────────┐
       │ (amber) │                     │
       └────┬────┘                     ▼
            │ user "괜찮아"      ┌─────────┐
            │ OR timeout 5min   │ RESCUE  │
            ▼                    │ (주홍)  │
       ┌─────────┐               └────┬────┘
       │ NORMAL  │◄───────────────────┘ user "고마워"
       └─────────┘                       OR alt POI like

전이 룰:
- NORMAL → ALERT: weather/POI trigger 발생 시
- ALERT → RESCUE: ALERT 중 사용자가 RESCUE 발화 시 (ALERT 우선순위 ↓)
- RESCUE → NORMAL: 사용자 acknowledge OR 대안 POI like
- ALERT → NORMAL: 사용자 "괜찮아" OR 5분 dormant
- AWAY는 직교 (네트워크 상태). 어느 state에서든 진입 가능
```

**데이터 흐름 (현장 컴패니언 호출 1회) — D2 hallucination 방지 반영:**

```
1. 사용자 음성 입력 ("지금 어디 가볼까")
2. expo-speech-recognition → 텍스트
3. expo-location → 현재 GPS 좌표
4. companion/llm-orchestrator.ts:
   a. poi.ts → 카카오 API (좌표 + 카테고리 CE7/FD6/AT4) → 근처 5개
      • 각 POI는 { id, name, address, category, hours? } 구조
   b. LLM 호출 (백엔드 proxy 경유) — ★ 구조화 응답 강제:
      - system prompt: user style + 사용자 발언 + 카카오 5개 (id 포함)
      - response_format: JSON
        {
          "recommended_ids": ["kakao_id_1", "kakao_id_2"],  // ← Kakao id에서만 선택
          "note": "근처에 ㅇㅇ 카페가 있어요. 비 와도 괜찮아요"
        }
   c. 응답 streaming + validate:
      • recommended_ids가 카카오 5개 id 안에 없으면 → fallback 멘트
      • LLM이 자유 POI 이름 만들어내는 hallucination 차단
5. companion/card-resolver.ts → card type 결정 (NORMAL/ALERT/RESCUE/AWAY)
6. tts.ts → Edge TTS (note 텍스트 → mp3 stream)
7. track-player → 백그라운드 재생
8. 화면에는 검증된 카드 1-2개 표시 (id로 카카오 detail 다시 조회)
```

## DevOps (Pre-commit + CI/CD — D11)

### Pre-commit hook (husky 9 + lint-staged)

**왜 husky?** 초기 simple-git-hooks 시도 → bun의 `.bun/<pkg>@<ver>/` 디렉터리 구조와 postinstall 호환 X (CI 환경에서도 동일 fail). 실제 결과 보고 husky 9 로 교체 (Day 2b 중 발생, D11 갱신). husky는 npm/bun/yarn 모두 검증된 standard.

**package.json (root) 설정:**

```json
{
  "scripts": {
    "prepare": "husky"
  },
  "lint-staged": {
    "*.{ts,tsx,js,jsx,json,md,yml,yaml}": ["biome check --write --no-errors-on-unmatched"]
  },
  "devDependencies": {
    "husky": "^9.1.7",
    "lint-staged": "^15.x"
  }
}
```

**`.husky/pre-commit`:**
```sh
bun run lint-staged && bun run typecheck
```

**셋업:** `bun install` 시 `prepare = husky` 가 자동 실행 → `.husky/_/` wrapper 생성 + `git config core.hooksPath .husky`. 매 clone/CI 후 동일하게 동작.

**typecheck**는 turbo로 — root에 `"typecheck": "turbo run typecheck"` 추가, 각 패키지에 `"typecheck": "tsc --noEmit"`. Turborepo 캐싱으로 변경 없으면 1초 안에 끝.

**실패 정책:** pre-commit 실패 = 커밋 차단. `--no-verify` 사용 금지 (CLAUDE.md 룰 일관). 정말 우회 필요시 별도 브랜치 + WIP commit.

## Worktree Parallelization

모노레포 + 3 컨테이너 구조로 *3 병렬 lane* 가능:

| Lane | 패키지 | 의존 |
|---|---|---|
| A | `packages/mobile-web/` (Expo 모바일+웹) | shared types (선택) |
| B | `packages/server/` (Hono + CC CLI route) | shared types |
| C | `packages/ai-tts/` (Python FastAPI) | — |

**병렬 실행 순서:**
- Day 1-2: 3 lane 동시 셋업 (docker-compose 인터페이스만 먼저 합의)
- Phase 3-7: A 위주 진행, B는 화면 진입 직전에 라우트 추가, C는 Phase 5 진입 직전에만 손댐

**1인 개발이면:** worktree로 분리할 필요까지 X. 한 repo 안에서 `bun --filter` 로 패키지 별 실행. 단 *Claude Code 병렬 작업* 시 lane 분리 유의미 (이 lane 끼리 충돌 적음).

**Conflict flags:** A의 services/api-client.ts ↔ B의 라우트 시그니처. shared/types/ 에 한 군데 정의해서 양쪽 import.
